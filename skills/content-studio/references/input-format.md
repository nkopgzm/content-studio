# 离线检查输入

使用 Python 3.10+。UTF-8 JSON 根对象含非空数组 `posts`，可选 `profile` 和 `history`。每条作品的 `body` 必须是非空字符串。仅用于用户明确交付的本次内容，不扫描其他资料。

```json
{
  "profile": {
    "required_tags": ["#创作练习"],
    "forbidden_phrases": ["保证涨粉"],
    "max_body_chars": 500,
    "identity_anchors": {"hair_color": "蓝色", "accessories": "圆框眼镜"},
    "min_visual_changes": 2
  },
  "posts": [{
    "id": "draft-01",
    "title": "把难写的开头缩小一点",
    "body": "今天先写一个具体场景：打开空白文档时，你的手停在了哪里？从这个动作开始，再慢慢写到想表达的观点。",
    "tags": ["#创作练习", "#写作"],
    "screen_text": ["从一个具体动作开始"],
    "visual": {
      "identity": {"hair_color": "蓝色", "accessories": "圆框眼镜"},
      "background": "窗边书桌",
      "composition": "侧面中景",
      "outfit": "米色衬衫"
    },
    "sources": []
  }],
  "history": []
}
```

`required_tags`、`forbidden_phrases` 是非空字符串组成的数组；`identity_anchors` 是字符串到非空字符串的映射。
标签忽略首尾的 `#` 和空格，并做 NFKC、大小写规范化，因此 `#创作练习`、`创作练习`、`#创作练习#` 等价；只有 `#` 和空白的值（如 `# #`）无效。规范化后相同的禁用短语只检查一次，报告保留列表中的第一种写法。
`screen_text` 是可选的非空字符串数组，默认 `[]`，用于单独记录画面字幕。禁用短语检查覆盖标题、正文、独立标签和 `screen_text`，正文长度和重复检查均不包含 `screen_text`。
禁用短语在每个字段（包括每个标签、每条字幕）内独立做规范化后的字面子串匹配，不跨字段拼接；不能识别插入空格、拆字或同义改写，这些情况仍需人工审查。
短视频的 `body` 只填写口播内容；分镜、时间安排和拍摄说明放在另一个供人阅读的稿件文件，不放入检查器 JSON，也不混入 `body`。
`max_body_chars` 是用户指定的正文字符限制，不含标题、独立标签和 `screen_text`；正文内实际写入的空白、换行及标签仍计数。不等同于任何平台的长度计数规则。
它只检查上限，不能证明最少字数、纯汉字字数或视频时长；这些条件需要另外验证。
`min_visual_changes` 是背景、构图、服装三项中要求改变的项数，整数 0–3；默认 2。0 关闭视觉变化比较。
`history` 是用户提供的旧作品，只用于与新稿比较，不重新评判旧作品本身。
`sources` 仅记录人工事实审阅引用，支持非空字符串或非空对象组成的数组；对象的键和值均须为非空字符串。脚本不请求其中的网址，也不核实来源。

脚本对正文字符规范化后进行重复比较，不自动剥离正文中的标签词；独立 `tags` 数组和标题不参与比较。
规范化后不足 16 个字母或数字字符的正文不判断重复；存在其他本批作品或历史记录时，每条新稿最多出现一次 `TEXT_TOO_SHORT` 警告，提醒人工复核。16–39 字符正文完全相同只给出 `SHORT_TEXT_MATCH` 警告；40 字符及以上完全相同为错误，近似重复为启发式警告。
精确重复与较长正文的近似重复是可解释的词面结果，不代表已经判断语义重复或抄袭。
视觉字段按文本比较，只能发现简报设定的差异，不能识别图片内容。缺失资料应保留警告，不编造补齐。
`visual.identity` 中省略或留空的身份值会产生 `IDENTITY_UNCHECKED` 警告（仅针对配置了的身份锚点）；`profile.identity_anchors` 的目标值仍必须非空。
身份锚点是规范化后的精确枚举值，例如 `蓝色短发` 不等于 `蓝色`；identity 中填与目标一致的固定值，额外形容词放在检查器 JSON 之外的视觉简报文字里。背景、构图、服装的同义表述也不会被自动认定为同一场景，必须由宿主模型结合用户原稿进行语义审查，必要时交由用户确认。
缺少可选资料时省略该字段，不要写 `null`。`null`、错误类型和未知字段属于输入格式错误，退出码为 2；不会被当成检查通过。`screen_text` 若无字幕可以省略或使用 `[]`，不要填写空字符串元素。

输出是 JSON，包含 `schema_version`、`summary` 与 `findings`。每条 finding 提供严重程度、规则代码、作品标识和解释；重复比较可能含关联作品标识。
`summary.passed` 代表本次配置下没有 error，并不表示没有 warning，也不代表内容可以直接发布。

在技能目录运行：`python scripts/audit_content.py --input batch.json --output report.json`。
退出码 0：无内容 error；1：有内容 error；2：输入或文件操作失败。输出文件必须使用新路径，不覆盖原稿。
